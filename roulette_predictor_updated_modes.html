Notes: ordering, persistence, algorithm, limitations
  • Ordering. Initial input is oldest→newest. Internally records[] is newest-first; each Save inserts at index 0. Nothing is ever discarded. Analytics always use records.slice(0, 37).
  • Persistence. Saved in this browser's localStorage (key rv_session_v1) after every accepted change; a failed write is reported and the change is rolled back. Export/Import use JSON. Private/blocked-storage modes may prevent saving. Clearing site data erases the session, so export backups.
  • Candidate scoring (deterministic). Sources = the 3 newest records, weights 3/2/1 (newest first). Candidates = union of configured mappings for those sources (sources 0 and 19–36 have no mapping and are skipped). Score = 42% pattern (source-weight sum ÷ max) + 36% hot/cold (75% membership in Hot5/Cold5 + 25% relative frequency) + 22% history (65% relative frequency + 35% occurrences in newest 10). Ties: score desc, then number asc. These weights come from the supplied file.
  • Unlimited use. After one successful Save, the Predict button stays enabled and can be pressed any number of times; each press is logged. A new Save is needed only to change the data.
  • Fallback. If fewer than 5 mapped candidates exist, deterministic fallback candidates are filled from remaining 0–36 using hot/cold membership, relative frequency, newest-10 frequency, then number ascending. They are visibly labeled.
  • Wheel neighbours. Not used in scoring, because the owner has not defined the rule. Standard European wheel order is stored as WHEEL_ORDER for a future rule.
  • Limitations. Scores are heuristic rankings, not probabilities or winning chances. Hot/cold, mappings and neighbours confer no edge on independent spins. Do not use this to chase losses or as a betting system.
